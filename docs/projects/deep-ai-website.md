# DEEP-AI 웹사이트 프로젝트 — 전체 내용 흐름 시안

작성일: 2026-09-19 · 상태: initial / 콘텐츠 및 Figma 디자인 검토용

## 이번 시안의 범위와 근거

Figma 시각 설계에 앞서 검토할 콘텐츠 순서, 제목·본문 초안, 시각 자료의 역할을 정리한다. 이후 제작한 Figma 검토 시안은 문서 하단에 기록한다. 웹 구현은 아직 진행하지 않았다.

- 기존 프로젝트 정보: `src/data/projects.ts`의 `paia` 항목.
- 기존 본문: `src/content/projects/paia.tsx`. 아래 사실 서술은 이 원고를 바탕으로 재구성했으며 외부 검증을 완료했다는 의미는 아니다.
- 서사 참고: `src/content/projects/ndt.tsx`, `docs/projects/deep-ndt.md`.
- DEEP-NDT의 개요 → 상황 → 목표와 두 핵심 과제 → 개선 사례 → 결과 → 회고 흐름을 참고한다. 소프트웨어 도메인 설명과 프로젝트 전용 지표·인용·파란 카드 표현은 가져오지 않는다.
- 기존 코드의 식별자 `paia`는 유지한다. 별도 프로젝트인 `deep-ai` 브랜드 에셋과 구분한다.

## 이야기의 중심

**회사와 기술을 소개하던 웹사이트를, 고객 문의와 채용 지원이 운영으로 이어지는 접점으로 바꾸다.**

포트폴리오 독자가 따라갈 질문은 다음과 같다.

1. 회사 소개 웹사이트에 왜 변화가 필요했는가?
2. 방문자가 기술을 이해하고 다음 행동을 선택하도록 무엇을 정리했는가?
3. 문의와 지원이 접수 이후 실제 운영으로 이어지도록 무엇을 설계했는가?
4. 어떤 결과를 확인했으며, 무엇은 아직 확인하지 못했는가?

브랜드의 사고 흐름은 기존 경로의 한계 관찰 → 방문 목적과 기술 정보 연결 → 탐색·접수 구조 설계 → 콘텐츠 제작·퍼블리싱·운영 연결로 드러낸다. 실제 조사 방법과 사용 기록이 없는 부분에 인터뷰나 분석 과정을 만들어 넣지 않는다.

## 01. 프로젝트 소개

**프로젝트명**

비파괴검사 솔루션 기업 DEEP-AI 웹사이트

**대표 문장 초안**

회사와 기술의 소개를, 고객 문의와 채용 지원으로 연결하다.

**도입 문장 초안**

회사와 제품을 소개하던 웹사이트를 비즈니스 문의와 채용 지원을 접수하고 관리하는 서비스로 개편했습니다.

**시각 자료**

기존 대표 이미지 `public/images/projects/paia/cover2.jpg`를 우선 후보로 둔다. 실제 시안에서는 이미지의 가독성과 이번 서사의 적합성을 확인한다. 첫 장면에는 프로젝트 정체성과 결과를 보여주고, 상세 역할은 다음 개요에서 설명한다.

## 02. 프로젝트 개요와 역할

**제목 초안**

웹사이트의 탐색부터 접수 이후의 운영까지 설계했습니다.

**본문 초안**

DEEP-AI는 비파괴검사 솔루션을 제공하는 기업입니다. 이번 리뉴얼에서는 방문자가 회사의 기술과 솔루션을 이해한 뒤, 도입 문의나 채용 지원으로 이어질 수 있도록 웹사이트를 재구성했습니다.

디자이너이자 PM으로 외부 기획자와 서비스 구조를 기획하고, 콘텐츠 기획·제작, UX/UI 디자인과 웹 퍼블리싱을 담당했습니다. 개발팀과는 문의 및 지원 정보를 실제로 관리할 수 있도록 기능과 데이터 구조를 조율했습니다.

| 항목 | 기존 기록 |
|---|---|
| 기업/클라이언트 | DEEP-AI |
| 기간 | 2026. 6. – 2026. 7. |
| 역할 | Project Manager, UX/UI 기획 및 디자인, 콘텐츠 기획 및 제작, 웹 퍼블리싱 |
| 팀 | 외부 기획자 1, Designer & PM 1(본인), 개발팀 2 |

**구성 메모**

DEEP-NDT의 공통 개요 구성을 따른다. 비파괴검사 도메인은 한 문장으로 소개하고, 이 사례에서는 웹사이트의 목적과 본인 기여에 집중한다.

## 03. 상황

**제목 초안**

기술을 소개한 다음, 방문자가 행동할 경로가 필요했습니다.

**본문 초안**

기존 웹사이트는 회사의 기술력과 제품 정보를 전달하는 데 집중되어 있었습니다. 관심을 가진 방문자가 상담이나 협업을 요청하도록 이어주는 경로는 충분하지 않았습니다.

리뉴얼에서는 정보 전달에 더해, 실제 비즈니스 문의를 확보하는 것을 웹사이트의 주요 목표로 삼았습니다. 채용 지원 역시 웹사이트 안에서 접수하고 관리할 수 있도록 범위에 포함했습니다.

**시각 자료 제안**

- 기존 상태: 회사·기술·제품 소개 중심.
- 목표 상태: 정보 탐색 → 도입·협업 문의 또는 채용 지원 → 접수 정보 관리.

이는 기존 원고를 요약한 개념 비교다. 실제 이전 사이트의 메뉴나 사용자 행동을 재현한 도식으로 표현하지 않는다. 이전 화면이 확보되면 비교 근거로 추가한다.

## 04. 목표와 두 핵심 과제

**제목 초안**

기술에 대한 관심이 문의와 지원으로 이어지는 웹사이트를 만든다.

**본문 초안**

방문자가 필요한 정보를 찾고 다음 행동을 선택하는 과정, 그리고 접수된 정보를 회사가 관리하는 과정을 함께 설계했습니다. 상세 페이지에서는 이 작업을 다음 두 과제로 묶어 설명합니다.

| 핵심 과제 | 설계의 초점 | 이어지는 사례 |
|---|---|---|
| 기술 정보와 방문 목적 연결하기 | 솔루션·적용 산업·기술 인증을 탐색 흐름에 맞게 정리하고 다음 행동 안내 | 사례 1 · 탐색과 콘텐츠 |
| 문의·지원을 운영으로 연결하기 | 목적별 접수 항목과 고객·지원자 정보 관리 구조 설계 | 사례 2 · 문의와 채용 |

두 과제는 기존 작업을 설명하기 위한 편집 구조이며, 당시 확정된 프로젝트 계획서의 직접 인용은 아니다.

## 05. 사례 1 — 탐색과 콘텐츠

**제목 초안**

기술을 이해한 순간, 다음 행동을 선택할 수 있도록.

**본문 초안**

솔루션과 서비스, 적용 산업, 기술 인증을 고객의 탐색 흐름에 맞춰 재구성했습니다. 각 페이지의 콘텐츠를 기획·제작하고, 도입 검토와 데모 신청, 기술 협업 등 다음 행동으로 이어지는 버튼과 링크를 배치했습니다.

**세부 장면 A · 기술과 적용 맥락 연결**

솔루션 소개와 산업별 소개 화면을 함께 보여줍니다. 무엇을 제공하는지와 어떤 현장에 적용되는지를 각각 어떻게 설명했는지, 실제 화면의 문구와 구조를 근거로 짚습니다.

**세부 장면 B · 정보 탐색에서 문의로 연결**

콘텐츠를 읽은 뒤 문의로 이동하는 지점을 확대해 보여줍니다. 버튼 개수를 강조하기보다, 해당 위치에서 왜 그 행동을 안내했는지 설명합니다. 구체적인 버튼명·위치·이동 목적지는 자산 확인 후 확정합니다.

**시각 자료 후보**

- `public/images/projects/paia/industries-full.png`
- 전체 화면 한 장으로 맥락을 제시한 뒤, 설명할 콘텐츠와 문의 연결 지점을 별도 확대하는 구성.

## 06. 사례 2 — 문의와 채용

**제목 초안**

문의와 지원이 접수 이후에도 쓰일 수 있도록.

**본문 초안**

도입·데모, 기술 협업, 투자 문의처럼 목적에 따라 필요한 입력 항목을 달리 설계했습니다. 접수된 고객 정보는 관리자 페이지와 데이터베이스에 연결해 관리할 수 있도록 개발팀과 조율했습니다.

채용은 자체 페이지와 상시 지원 경로를 마련하고, 지원자 정보를 지속해서 관리할 수 있는 채용 풀로 연결했습니다.

**세부 장면 A · 목적별 문의**

문의 목적 선택 → 필요한 정보 입력 → 접수 정보 관리의 관계를 보여줍니다. 입력 항목을 선택한 근거는 실제 폼과 요구사항을 확인해 보완합니다.

**세부 장면 B · 채용 지원**

채용 정보 확인 → 지원 → 지원자 정보 관리의 관계를 보여줍니다. 고객 문의와 채용 지원은 대상과 목적이 다른 두 흐름으로 구분합니다.

**시각 자료 후보**

- `public/images/projects/paia/deepai-3.png`: 기존 본문에서 사용하는 문의 화면.
- `public/images/projects/paia/deepai-4.png`: 기존 본문에서 사용하는 채용 화면.
- `contact-full.png`, `career-full.png`도 보유 중이며, 최종 시안 전 버전과 내용 차이를 확인한다.
- 관리자 화면은 공개 가능한 자료가 있을 때만 사용한다. 없으면 확인된 범위의 개념 연결도로 대체한다.

## 07. 제작과 협업

**제목 초안**

구조 기획부터 콘텐츠와 퍼블리싱까지 연결했습니다.

**본문 초안**

외부 기획자와 서비스 구조를 정리하고, 각 페이지의 콘텐츠와 UX/UI 디자인을 제작했습니다. 웹 퍼블리싱까지 담당하면서 콘텐츠가 실제 화면으로 이어지도록 작업했습니다.

문의·채용 기능은 개발팀과 데이터 구조를 조율해 구현으로 연결했습니다.

**구성 제안**

개요의 역할 목록을 반복하기보다, 실제 협업 산출물 한 가지를 근거로 보여주는 짧은 섹션으로 둡니다. 콘텐츠 구성표, 화면과 접수 항목의 대응, 개발 협의 자료 중 공개 가능한 자료가 적합합니다. 별도 근거가 없으면 이 섹션을 개요와 사례 2에 합쳐 분량을 줄입니다.

**TBD**

AI 활용의 실제 범위와 사례. 프로젝트에는 `AI-Enhanced Workflow` 분류가 있으나, 현재 본문만으로는 사용 도구·공정·검수 방법을 알 수 없다. 확인 전에는 AI 제작 과정이나 시간 절감 효과를 서술하지 않는다.

## 08. 결과

**제목 초안 — 기존 원고 기준, 공개 전 근거 확인**

배포 이틀 만에 실제 비즈니스 고객의 문의를 확보했습니다.

**본문 초안**

배포 후 이틀 만에 실제 비즈니스 고객의 문의가 접수되었습니다. 회사와 기술을 소개하는 웹사이트에 문의와 채용 지원 경로, 접수 정보를 관리하는 구조를 마련했습니다.

초기 문의 접수는 확인된 반응으로 제시하고, 문의가 계약이나 매출로 이어졌는지는 별도로 구분합니다.

**보여줄 결과**

| 구분 | 기존 원고에 있는 내용 | 표현 범위 |
|---|---|---|
| 초기 반응 | 배포 이틀 만에 실제 비즈니스 고객 문의 확보 | 문의 건수·고객명·전환율은 추정하지 않음 |
| 구축 결과 | 목적별 문의와 관리자·데이터베이스 연결 | 운영 효율 증가를 수치로 주장하지 않음 |
