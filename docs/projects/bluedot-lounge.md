## 반응형과 접근성

- 48rem 미만: 앱·키오스크·편의 기능 이미지를 가로 스크롤과 위치 버튼으로 제공한다. 다음 이미지 일부가 보여 넘길 수 있음을 알린다. 이미지 내부 문구를 억지로 축소하지 않는다.
- 좌우 키와 위치 버튼으로 이미지 이동, reduced motion에서는 즉시 이동한다. 자동 재생은 없다.
- 제안서 5장은 모바일에서 한 장씩 좌우로 넘기는 슬라이드로 제공한다. 위치 버튼·키보드 이동·이미지 확대를 지원하고, 브로슈어 목업은 슬라이드 아래에 별도로 둔다. 48rem 이상은 표지 전체 너비 + 내지 2열의 기존 구성을 유지한다.
- 매장·SNS 이미지들은 모바일에서 세로로 재배치한다. 작은 원본 캐릭터는 불필요한 확대를 제공하지 않는다.
- 충분한 해상도의 화면·목업은 native dialog로 확대한다. 닫기 버튼·Escape·배경 클릭으로 닫고 원래 버튼으로 포커스가 돌아간다.
- 모바일은 설명–이미지 80px, 섹션 간 160px의 기존 상세 페이지 리듬을 유지한다. 회고는 긴 본문의 가독성을 위해 전체 열을 사용한다.
- 모바일 Hero는 중앙 크롭과 30% 어두운 오버레이로 제목 대비를 보완한다. 큰 화면은 Figma 크롭을 따른다.
- 48rem 이상은 다열 배치, 75rem 이상은 시안의 좌측 라벨 열과 우측 본문 열 정렬을 적용한다.

## 구현 범위

- `bluedot.tsx`: 공통 개요·제목·회고와 프로젝트 콘텐츠.
- `bluedot-media.tsx`: 이미지 확대와 모바일 화면 갤러리.
- `bluedot.module.css`: 프로젝트 전용 반응형 규칙.
- KIT 상세가 이전 Bluedot CSS를 공유하고 있었으므로 해당 스타일을 `kit.module.css`로 분리해 기존 화면을 보존했다.
- 기본 타입 검사, 린트, `/portfolio` base path를 포함한 정적 빌드를 통과했다. 홈·목록의 대표 이미지, 상세 자산 경로와 키보드 확대/닫기·포커스 복귀를 확인했다. 320px·390px·768px·1440px·1920px 브라우저에서 레이아웃과 이미지 로딩을 확인했다. 실제 모바일 기기에서 사용자와 확인하는 후속 검수는 별도다.
