# Voice and Writing

## 1. Voice

브랜드의 목소리는 **관찰력이 있고, 명료하며, 절제되고, 실용적**이다. 잘 알고 있음을 과시하기보다 독자가 복잡한 생각을 쉽게 따라오도록 편집한다.

### Desired qualities

- **구체적** — 추상적 가치 대신 상황과 선택을 말한다.
- **차분한 자신감** — 과장 없이 판단의 근거를 보여준다.
- **호기심** — 결론만 선언하지 않고 발견의 출발점을 남긴다.
- **구조적** — 문단마다 하나의 역할이 있고 흐름이 명확하다.
- **인간적** — 지나치게 기업적이거나 기계적인 문장을 피한다.
- **쓸모 지향적** — 독자가 무엇을 이해하거나 할 수 있게 되는지 고려한다.

## 2. Tone by Context

| 맥락 | 톤 | 주의점 |
|---|---|---|
| Home | 압축적, 선명함 | 슬로건을 장황하게 해설하지 않기 |
| Work | 구체적, 분석적 | 성과 과장과 영웅 서사 피하기 |
| Observations | 호기심, 개방적 | 모든 관찰을 큰 인사이트로 포장하지 않기 |
| Experiments | 솔직함, 탐구적 | 실패를 감추거나 교훈을 억지로 만들지 않기 |
| About | 따뜻함, 직접적 | 추상적인 자기 수식어 나열 피하기 |
| Navigation/UI | 짧고 예측 가능 | 개성 때문에 이해를 희생하지 않기 |

## 3. Language Roles

영문과 한글은 동일한 내용을 병기하는 두 버전이 아니라 서로 다른 역할을 담당한다.

### Visual Voice — English

- 인상, 리듬, 태도와 장면 전환을 만든다.
- Hero와 중요한 서사 전환에서 크고 압축적인 타이포그래피로 제한적으로 사용한다.
- 확정 문구는 `OBSERVE. CONNECT. MAKE IT USEFUL.`이다.
- 단어의 순서와 마침표는 유지한다.
- 영문 캐치프레이즈를 모두 대문자로 표기해야 한다는 규칙은 두지 않는다. 화면의 조형과 어조에 따라 `Observe. Connect. Make it useful.`처럼 대소문자를 조정할 수 있다.
- 대표 영문 소개 문장처럼 장황하게 확장하지 않는다.

### Information Voice — Korean

- 의미, 맥락, 근거, 구체적인 행동과 안내를 전달한다.
- 공식 슬로건, 본문, 프로젝트 과정, 관찰과 실험 기록, UI 안내의 기본 언어로 사용한다.
- 영문의 분위기를 반복 번역하기보다 독자가 실제로 이해해야 할 내용을 완성한다.

Visual Voice는 모든 섹션 제목과 라벨에 확장하지 않는다. 의미 없는 영문 대문자, 분위기용 전문 용어와 같은 장식적 사용은 계속 피한다.

## 4. Core Language

가능하면 다음 의미장을 일관되게 사용한다.

- 발견하다, 관찰하다, 알아차리다
- 연결하다, 관계를 찾다, 이어 보다
- 구조화하다, 정리하다, 편집하다
- 정제하다, 덜어내다, 명료하게 하다
- 쓰이다, 작동하다, 쓸모 있게 만들다

키워드를 모든 문장에 반복하지 않는다. 실제 사고와 행동이 드러나는 곳에서만 사용한다.

## 5. Writing Rules

- 한 문장에는 가능하면 하나의 핵심 생각만 둔다.
- 능동형과 구체적인 동사를 우선한다.
- “다양한”, “혁신적인”, “효과적인”, “사용자 중심적인” 같은 수식어는 근거가 있을 때만 쓴다.
- “~를 통해”, “~에 대한”, “~할 수 있는”의 연속 사용을 줄인다.
- 긴 영문 제목이나 전문 용어를 분위기용으로 사용하지 않는다.
- 독자가 모를 수 있는 약어와 업계 용어는 처음에 풀어 쓴다.
- 프로젝트의 공동 작업을 개인 단독 성과처럼 쓰지 않는다. 역할과 기여를 분명히 한다.
- 수치와 성과에는 출처 또는 측정 맥락을 둔다.
- 미확정 내용은 그럴듯한 정보로 채우지 않고 `TBD` 또는 명시적인 placeholder로 둔다.

## 6. Slogan Usage

공식 슬로건 표기는 다음과 같다.

> 관찰하고, 연결하여, 쓸모있게.

- 쉼표와 마침표를 포함한 표기를 기본으로 한다.
- Hero에서 줄바꿈할 수 있지만 어순과 문구는 바꾸지 않는다.
- 모든 페이지에서 반복 노출하지 않는다.
- 공식 영문 Visual Voice는 `OBSERVE. CONNECT. MAKE IT USEFUL.`이다.
- 영문 표기의 대소문자와 반응형 줄바꿈은 조형 목적에 따라 바꿀 수 있지만 단어의 순서와 마침표는 유지한다.

### Plain-language principle

- 고객이 브랜드의 내부 맥락을 미리 알고 있다고 가정하지 않는다.
- 철학과 전략을 먼저 설명하기보다 실제로 무엇을 보고, 정리하고, 만드는지 일상적인 동사로 말한다.
- Process를 설명할 때는 각 행동이 고객에게 어떤 이해, 기준 또는 결과를 주는지 바로 연결한다.
- “의미 있는 관계”, “명료한 경험”, “비즈니스 임팩트” 같은 추상 표현은 구체적인 상황이나 변화가 뒤따를 때만 사용한다.

## 7. Example Direction

### Prefer

- “흩어진 인터뷰 기록에서 반복되는 불편을 발견했습니다.”
- “세 가지 사용 맥락을 하나의 탐색 구조로 연결했습니다.”
- “기능을 더하기보다 선택 단계를 줄여 실제 사용 흐름을 정제했습니다.”
- “이 실험은 완성된 답보다 다음 질문을 선명하게 만들었습니다.”

### Avoid

- “사용자 중심의 혁신적인 경험을 디자인합니다.”
- “무한한 가능성을 연결하는 크리에이티브 디자이너입니다.”
- “트렌디하고 감각적인 디자인으로 비즈니스 임팩트를 창출합니다.”
- “세상을 바꾸는 디자인을 믿습니다.”

피해야 할 문장도 사실과 근거가 추가되면 사용할 수 있지만, 선언만으로는 브랜드를 증명하지 못한다.

## 8. UI Copy

- 내비게이션은 `Work`, `Observations`, `Experiments`, `About`처럼 예측 가능한 이름을 쓴다.
- “자세히 보기”보다 목적이 드러나는 링크를 쓴다. 예: “프로젝트 과정 보기”, “관찰 기록 읽기”.
- 외부 링크, 다운로드, 새 창 등 결과가 달라지는 동작은 필요할 때 명시한다.
- 오류 메시지는 문제와 다음 행동을 함께 알려준다.
- 버튼을 전부 명사형 또는 전부 문장형으로 억지로 통일하기보다 맥락에 맞추되 같은 종류에서는 일관성을 유지한다.

## 9. Language Policy

현재 기본 작성 언어는 한국어로 가정한다. 영문은 고유명사, 프로젝트 맥락, 편집적 대비에 필요할 때 제한적으로 사용할 수 있다.

한영 병기 또는 완전한 다국어 지원은 **TBD**다. 결정 전에는 동일 내용을 두 언어로 반복해 화면 밀도를 높이지 않는다. 영문 display 사용 시에도 핵심 정보는 한국어 사용자에게 접근 가능해야 한다.
